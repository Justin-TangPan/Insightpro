# InsightPro 运维手册

## 架构总览

生产环境使用 Docker Compose 部署两个容器：

| 容器 | 镜像 | 端口 | 基础镜像 |
|------|------|------|---------|
| `insight-frontend` | `insight-web-frontend:0.0.x` | `0.0.0.0:3000` | Node.js 20-slim（Next.js standalone） |
| `insight-backend` | `insight-web-backend:0.0.x` | `0.0.0.0:8000` | Python 3.11-slim |

两个容器均以 UID/GID 10001 非 root 用户运行，通过内部 Docker 网络 `insight-network` 通信。

## 开机自启方案

### 自启链路

```
系统开机
  └─ systemd (PID 1)
       ├─ docker.service                         (enabled)
       │    └─ Docker daemon 启动，可用 API version 1.39
       ├─ insight-docker-compose.service         (enabled)
       │    ├─ down --remove-orphans  (清理可能残留的旧网络/容器)
       │    └─ up --detach            (启动前后端容器)
       └─ insight-docker-health-guard.timer     (enabled)
            └─ 开机 2 分钟后首次巡检，之后每 10 分钟一次
                 ├─ 健康 → 跳过
                 ├─ 容器/网络异常 → down + up 重建
                 └─ 数据不新鲜 → 容器内 maintenance.py repair-freshness
```

### 为什么不用 `restart: unless-stopped`

Docker Engine 18.09 在 daemon 重启后，`restart: unless-stopped` 无法可靠恢复容器——旧容器的网络引用会失效（`network not found`）。因此本项目使用 systemd `insight-docker-compose.service` 作为第一层保障，先清理旧状态再重建。

### 验证开机自启

```bash
# 检查各链路是否均已 enable
systemctl is-enabled docker
systemctl is-enabled insight-docker-compose.service
systemctl is-enabled insight-docker-health-guard.timer

# 依赖链
systemctl list-dependencies insight-docker-compose.service
```

## 常用命令

```bash
# API 兼容参数（旧 Engine 必需）
export DOCKER_API_VERSION=1.39

# 容器状态
docker-compose -p insight-web -f compose.yaml ps

# 查看日志
docker-compose -p insight-web -f compose.yaml logs --tail 100
docker-compose -p insight-web -f compose.yaml logs -f             # 实时跟随

# 重启（不重建镜像）
docker-compose -p insight-web -f compose.yaml restart

# 停止
docker-compose -p insight-web -f compose.yaml down

# 启动（重新创建网络/容器）
docker-compose -p insight-web -f compose.yaml up --detach

# 完整健康验收
./scripts/health-check.sh full

# 查看巡检日志
journalctl -u insight-docker-health-guard.service -n 50 --no-pager

# 标准发布（测试 → lint → 构建 → 切换，失败自动回退）
sudo ./scripts/deploy-docker.sh
```

## 健康判定

`health-check.sh` 支持两种模式：

### infra（基础设施）
- 后端存活探针 `/api/system/health/live` → `alive`
- 前端首页 `http://127.0.0.1:3000/` → 200
- 同源代理存活探针 `http://127.0.0.1:3000/api/system/health/live` → `alive`

### full（端到端数据链路）
- infra 全部通过
- 后端就绪探针 `/api/system/health/ready` → `healthy`（含 PostgreSQL 连接和数据新鲜度）
- 前端同源就绪探针同上
- 技术业务价值评估非空且关键字段完整

## 自动修复逻辑

健康守护脚本 `scripts/docker-health-guard.sh` 逻辑：

1. 健康 → 直接退出，不执行任何操作。
2. **容器/网络异常**（infra 检查失败）：
   - `down --remove-orphans` 清理过期网络和容器
   - `up --detach --remove-orphans` 重建
   - 等待 60 秒（30 次 × 2 秒），仍失败则重启容器
   - 仍不可恢复 → 写入 journald 并触发 Webhook 告警
3. **数据不新鲜**（infra 通过但 full 失败）：
   - 检查冷却时间（默认 1 小时），防止重试风暴
   - 在后端容器内执行 `maintenance.py repair-freshness`
   - 等待最多 5 分钟（60 次 × 5 秒）让数据就绪
4. 持续故障 → 通过 `INSIGHT_ALERT_WEBHOOK` 发送告警 JSON。

## 告警配置

在根目录 `.env` 添加：

```dotenv
INSIGHT_ALERT_WEBHOOK=https://your-domain.com/webhook
```

Webhook 接收 `{"text":"消息内容"}` JSON POST。修改后无需重启，下次巡检生效。

## 发布流程

```bash
# 标准发布（含测试、lint、构建、切换、验收）
sudo ./scripts/deploy-docker.sh

# 仅构建镜像
export DOCKER_API_VERSION=1.39
docker-compose -p insight-web -f compose.yaml build

# 手动替换容器（不跑测试）
docker-compose -p insight-web -f compose.yaml up --detach --build
```

发布脚本 `deploy-docker.sh` 门禁：
1. 获取部署锁（互斥）
2. 后端 `pytest` 通过
3. 前端 `npm run lint` 通过
4. 构建新镜像
5. 安装健康守护 systemd 配置
6. 禁用旧 systemd 服务 → 标记切换点
7. `compose up --detach`
8. 最长 3 分钟健康等待（180 次 × 1 秒）
9. 验收通过 → 启用健康守护定时器
10. 验收失败 → 自动回退旧 systemd 部署

## 数据补跑

```bash
# 手动执行数据补跑
export DOCKER_API_VERSION=1.39
docker-compose -p insight-web -f compose.yaml exec backend python maintenance.py repair-freshness
```

补跑按以下依赖顺序执行：
1. GitHub Trending
2. 百度热搜
3. 新闻/政策/厂商
4. 友商
5. 招标
6. 需求
7. 技术评估

同一数据集当天已有数据则跳过（幂等）。PostgreSQL advisory lock 保证多实例不重复执行。

## 巡检定时器管理

```bash
# 查看定时器状态
systemctl status insight-docker-health-guard.timer

# 查看最近一次巡检结果
journalctl -u insight-docker-health-guard.service -n 20 --no-pager

# 手动触发一次巡检
systemctl start insight-docker-health-guard.service

# 禁用巡检（不推荐）
systemctl disable --now insight-docker-health-guard.timer
```

## 故障排查

### 容器启动后立即退出

```bash
docker logs insight-backend --tail 50
docker logs insight-frontend --tail 50
```

常见原因：
- `network not found` → 执行 `docker-compose down` 再 `up`
- 端口被占用 → `netstat -tlnp | grep -E '3000|8000'`
- `.env` 缺少必要变量 → 检查 `docker-compose config`

### 健康检查失败

```bash
# 逐步排查
./scripts/health-check.sh infra      # 基础设施
./scripts/health-check.sh full       # 数据链路
curl -s http://localhost:8000/api/system/health/ready | python3 -m json.tool
```

### 前端页面空白

1. 确认后端就绪：`curl http://localhost:8000/api/system/health/ready`
2. 检查同源代理：`curl http://localhost:3000/api/system/health/live`
3. 查看前端容器日志：`docker logs insight-frontend --tail 50`
4. 确认浏览器控制台无 CORS 错误

## 已知遗留

- Docker Engine 18.09 较旧，Compose 需 `DOCKER_API_VERSION=1.39`；建议在单独维护窗口升级至 20.10+
- 镜像仅保存在本机，新服务器需配置企业镜像仓库
- 无 HTTPS 反向代理（Nginx/Caddy 未配置）
- 无浏览器 E2E 监测
- DeepSearcher 依赖可选，未默认安装
