# InsightPro · AI Radar 改版说明

## 1. 产品定位与判断路径

**InsightPro：AI 产业雷达与洞察平台。** 核心承诺是“看见正在发生的 AI 变化，判断哪些值得行动”。目标用户是领导、业务负责人、产品经理和解决方案负责人；首页应让他们在 30 秒内看清：今天有什么变化、什么值得关注、对业务有什么意义、下一步做什么。

主链路：采集 → 清洗 → 实体与事件识别 → 跨来源聚类 → 热点与趋势判断 → Radar → 结构化 Insight → Agent 研究 → 行动。信息源是证据，**事件**是首页内容单元，**趋势**是跨事件的判断单元。AI Radar 是入口，Insight 是分析，Agent 承接深入研究和交付。

## 2. 信息架构与导航

| 一级入口 | 用户任务 | 主要内容 |
| --- | --- | --- |
| AI Radar | 30 秒掌握今日重点 | 今日摘要、Top Signals、五方向雷达、行动建议 |
| Trends | 判断行业风向 | 趋势列表、强弱变化、持续时间、代表事件 |
| Hot Apps | 发现新应用形态 | 今日新应用、本周爆发、快速增长、值得研究 |
| Insights | 解释信号与业务影响 | 事件结构化详情、深度报告、来源 |
| Watchlist | 跟进重要对象 | 事件、应用、趋势的负责人、状态和更新 |
| Insight Agent | 深入研究与产出 | 带上下文的研究任务与交付物 |

现有“项目洞察、云厂商方案、友商洞察、社区洞察、方案实践”保留为 Insights/工作台下的来源与分析视图，入口不应与 Radar 争抢首页主层级。详情页以稳定事件 ID 深链，来源文章留在详情的证据区。

## 3. Desktop 首页布局与模块内容

建议内容宽度 1200–1440px，12 栏栅格。首屏为一个紧凑的指挥摘要，不做大屏效果；第二屏开始展开证据。各区块需要更新时间、样本范围和空态。

1. **今日 AI Radar（12 栏）**：一句今日判断；今日采集动态、去重后重点事件、升温趋势、建议研究对象四个数；口径说明；一个“查看重点事件”主操作。数值均应可点击查看组成项。无可靠事件聚类时必须标“已采集信号”，不能冒称事件。
2. **Top Signals（左 8 栏）**：3–6 个事件，按 Radar Score、业务相关度和编辑校验排序。每条显示一句话解释、重要原因、趋势、业务影响、建议动作、来源数与可信度。右 4 栏放今日五方向雷达和方向列表。
3. **AI Trend Radar（12 栏或右侧延续）**：五个一级方向：AI 应用、Agent、模型与技术、AI Infra、商业化与产业。雷达图显示同一口径的趋势热度；紧邻数字与箭头列表，避免只靠图形或颜色传达。点方向进入 Trends 对应筛选。
4. **Hot AI Apps（左 6 栏）**：切换“今日新应用 / 本周爆发 / 快速增长 / 值得研究”。展示产品、公司、形态、一句话用途、创新点、增长证据、相关趋势、业务相关度。数据不足时用“待核实线索”，不填造增长值。
5. **Emerging Trends（右 6 栏）**：2–4 个尚未成为主流的趋势，显示近 7/30 天曲线、最早发现日、连续升温期、代表事件、反证和建议关注级别。
6. **Recommended Insights（12 栏）**：1–2 个建议重点研究对象，每条明确推荐原因、业务映射、待回答问题、负责人/跟进状态，主按钮进入结构化 Insight，次按钮让 Agent 带上下文研究。

## 4. 三种内容卡片

| 卡片 | 首层必显 | 展开/详情 |
| --- | --- | --- |
| Radar Event | 名称、一句话看懂、为什么重要、趋势、对我们意味着什么、影响高/中/低、建议动作 | Radar Score 六维解释、置信度、首次/最近发生、来源数、证据冲突 |
| Hot AI App | 产品/公司、一句话用途、形态、为什么突然受到关注、创新点、值得关注度、业务相关度 | 核心功能、增长/传播证据及区间、与既有产品相比的新变化、对应趋势、来源 |
| Trend | 名称、热度 0–100、↑/→/↓、近期代表事件、升温原因、持续时间、建议关注级别 | 7/30/90 天曲线、事件样本、反证、预测与复核日期 |

“为什么值得关注”必须指出相对基线的变化，例如新交互形态、跨厂商重复出现、增长加速或客户采用。普通发布消息不能仅凭热度进入 Top Signals。

## 5. Event 详情页与 Agent 上下文

详情页顺序：顶部结论（发生了什么、为什么重要、建议动作）→ 事件时间线与源数 → 核心产品/技术 → 行业背景与过去产品区别 → 所属趋势及关联事件 → 可能影响与竞争格局 → 商业模式/技术实现 → 华为云和内部 AI 应用、AgentArts、OfficeAce、开发工具、AI Infra、行业方案的关系 → 可借鉴点 → 风险与不确定性 → 行动清单与负责人 → 原始信息源。技术细节默认折叠，领导层先看到判断。

“AI 深入分析”将 `event_id`、事件版本、结构化字段、来源 ID、用户当前关注问题传给 Insight Agent；Agent 先引用证据，再给结论，不能只把页面标题当提示词。返回后支持将结论沉淀到 Insight 和 Watchlist。

## 6. 评分与趋势判定契约

事件六维分数均为 0–100：Heat（近 24/72 小时独立来源、传播速度）；Impact（影响的用户/产业环节与规模）；Novelty（相对已知产品和能力的差异）；Business Relevance（业务实体、产品能力与客户场景匹配）；Trend Strength（所属趋势近 7/30 天持续性与跨实体重复）；Confidence（独立一手源比例、事实一致性和证据完整度）。缺失维度显示“待评估”，不可用 0 代替。

**Radar Score = 0.15 Heat + 0.25 Impact + 0.15 Novelty + 0.25 Business Relevance + 0.20 Trend Strength。** Confidence 为发布门槛与分数折减：当 Confidence < 60，事件不得标“强烈建议关注”；展示分数时乘以 `0.7 + 0.3 × Confidence/100`，并展示原始维度。≥85 为重点研究，70–84 为持续跟踪，50–69 为观察，<50 默认不进首页。人工编辑可调整动作，但需留痕。业务相关度依用户/团队画像计算，公共榜单须标明画像。

趋势热度需按去重事件、独立实体、持续时间和证据质量计算；方向建议比较两个等长窗口并设置最低样本量。`↑↑` 为连续两窗口显著升温，`↑` 为本窗口升温，`→` 为平稳，`↓` 为回落。事件数、新闻数、趋势数、评分都必须保持独立口径。

## 7. 邮件 Radar Snapshot

邮件是 Radar 同一快照的分发：标题/日期与更新时间 → 今日一句判断 → 五方向雷达图及文字值 → 3–5 个最重要事件（事件一句话、重要原因、趋势）→ 今日趋势变化 → 1–2 个建议研究对象 → “进入 InsightPro 查看完整 AI Radar”。不在邮件塞全文。纯文本数值列表须伴随图表，兼容不显示图片的客户端；退订与订阅时间继续沿用现有机制。

## 8. 核心操作路径与状态

- 领导：打开首页 → 读今日判断和四数 → 扫 Top Signals/趋势 → 打开一个 Event → 标记“重点研究”并指派负责人。
- 产品经理：Hot Apps → 对比既有产品 → 加 Watchlist → 每周复核增长证据。
- 方案负责人：Radar Event → 业务映射 → AI 深入分析 → 形成方案实践/竞品分析。
- 数据不全：显示采集时间、来源范围与“待核实”；不显示虚假评分与增长箭头。无当日信号时保留近 7 天及上次更新时间。

## 9. 交付给 UI/UX 与前端的约束

视觉沿用平台现有深色表面与灰绿主题变量，细分割线、克制的雷达同心线；邮件采用浅底与同一灰绿强调色以适配邮箱。首页只给一个主操作；卡片标题建议 1–2 行，摘要 2 行；正文至少 14px。图表要有相邻数值、时间窗、图例和可访问文字，不能只用颜色表示上升。桌面优先，窄屏将 8/4、6/6 栏顺序堆叠，44px 以上点击目标。所有卡片应有来源与更新时间，外链标识明确。Loading、空态、API 失败、数据过期必须有专门文案。

## 10. 当前实现与下一阶段

当前实现共用的 **信号快照**：现有友商动态和 GitHub 项目提供五方向采集量与两段 7 天窗口对比；Product Hunt 官方 Feed 提供近期新 AI 应用发布线索。首页以小雷达、新应用和少量官方发布信号组织内容；邮件用同一份快照，采用浅色表格雷达、两款应用、最多三条其他信号与站内入口，并提供纯文本邮件。邮件不再使用内联 SVG，降低邮箱客户端出现黑框或空白图的概率。

当前方向分类与应用筛选是规则初筛，准确率未经验证；相同标题仅作基础去重。Product Hunt 的发布日期不等于用户增长或创新程度证据。尚无真实跨来源事件聚类、增长证据、趋势热度、Radar Score、Watchlist 或 Event 详情页。上线这些能力前，应建立事件/来源/趋势/应用的数据模型与审核流程。现有项目、方案、友商页面继续承担深度分析及证据入口。
