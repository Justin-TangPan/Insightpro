# InsightPro 改进清单

**基线日期**：2026-08-25

**状态**：当前技术债清单，不是承诺路线图

平台当前质量门禁、认证边界、数据契约、Docker 部署、健康检查和启动补跑均已落地。后续只在出现明确容量、可靠性或合规需求时处理以下事项，避免预先建设。

## 优先级清单

| 优先级 | 事项 | 当前风险 | 触发条件 | 最小处理方式 |
|---|---|---|---|---|
| P0 | 公网 HTTPS 边界 | 端口直出，不适合正式公网服务 | 面向公网开放前 | 增加 Nginx/Caddy、证书和只开放 80/443 |
| P1 | 调度器单实例限制 | 多 API 副本会重复调度 | 部署第二个后端副本前 | 独立 scheduler 或为全部任务加数据库租约 |
| P1 | 报告任务不持久 | API 进程重启可中断分析 | 报告成为关键交付或失败率不可接受 | 使用一套持久化任务队列 |
| P1 | 友商静态基准时效 | 人工字段可能失真 | 对照数据用于正式决策前 | 为每个字段补来源、采集时间和过期策略 |
| P1 | 依赖安全更新 | 已知依赖风险可能累积 | 月度维护或出现高影响公告 | 分批升级并跑完整门禁，禁止直接 `--force` |
| P2 | 浏览器 E2E | 健康检查不覆盖渲染错误 | 页面成为关键业务入口 | 增加登录、首页、专题页三个最小场景 |
| P2 | 镜像仓库 | 新机器依赖现场构建 | 建立多环境或灾备恢复 | 推送到企业镜像仓库并固定版本标签 |
| P2 | 语义检索 | 关键词召回能力有限 | 有检索质量样本证明漏召回 | 先用 PostgreSQL 全文检索，再评估向量索引 |
| P2 | `main_legacy.py` 收敛 | 部分采集逻辑边界不清 | 修改对应功能时 | 就地迁入已有 service；不做一次性大重构 |

## 固定质量门禁

每次可发布变更至少执行：

```bash
cd backend && STARTUP_CATCHUP_ENABLED=false python -m pytest -q
cd ../frontend && npm run lint && npm run build
cd .. && ./scripts/health-check.sh full
```

完成并验证修复后，更新 `log/versions.md`。数据库破坏性变更必须先备份和验证目标，生产密钥、日志与本地产物不得提交。

## 完成标准

- 修复落在真实共享边界，不在多个调用方重复打补丁。
- 代码、运行时接口、Prisma schema 和文档保持一致。
- 新能力有最小可运行验证；无法自动验证的风险明确写入版本日志。
- 没有真实触发条件的扩展设计不实施。
